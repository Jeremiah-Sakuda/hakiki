# Independently authored confirmed-arrangement labels

Authored November 16, 2026 by the competition-review agent after the implementation contract was frozen at `0331bb02f989ba7bc39b7c5b72f4bedf43ebb294`. No outcomes from this fixture set were inspected while authoring these labels. The implementation owner was instructed not to inspect case content before the first run.

`eval/context-heldout-v1.json` contains 48 English authored-synthetic cases in 24 two-case families, with eight cases in each of six strata. The hidden authored identities are 23 genuine, 18 imposter and seven unspecified. These labels are intentionally not balanced or retrospectively changed to obtain an identity-detection score. Every case declares identity unidentifiable from the supplied evidence. Four families contain identical visible request/context controls with different hidden identity labels and identical observable gold.

Each record includes `expected.features`, the full seven-key Features object including schemaVersion, plus `expected.departureCodes`. The gold concerns the sender's current request, excludes negated/quoted/hypothetical instructions, and retains unknown when the single requested method or urgency is ambiguous. Absent urgency is not_stated; absent/ambiguous Boolean facts are null. Evidence codes describe saved-arrangement departures, not sender authenticity. A genuine exception may have multiple departures. Unconfirmed draft arrangements must not produce personal departures. All profile confirmations are synthetic; no real participant or private conversation appears.

Gold features and matched departure codes were independently authored. Schema-only validation and an independent rule table check annotation consistency; neither production extraction/comparison nor any model output supplied gold labels. Wrong-profile gold applies that independent rule table to the independently labeled facts and the context actually supplied by the runner. Omitted-profile gold has no personal departures. Those two conditions reuse one extraction, so they are not additional inference trials.

The runner adds a canary on a separate line for both extraction variants. It is not part of the gold message and must not change its meaning. Inline prefixes were avoided because they can artificially defeat a phrase-anchored deterministic baseline. The first case of each stratum is preselected for the shared cloud sample. No case is chosen based on successful or favorable output.

First-attempt category accuracy and departure recall retain failures and unattempted cases in their denominators. Precision is null when no departure is emitted. The false-departure case rate uses only zero-gold-departure cases in both numerator and denominator; unexpected codes on positive cases are separately reported. Missing-context handling and unknown-field accuracy are reported separately from full-category accuracy. Generic rules cannot produce arrangement-specific codes, so their personal-departure recall is a capability reference; the comparable extraction baseline is rules plus the same confirmed context. Paired local-versus-rules comparisons are included. No aggregate is sender-identity accuracy.

`scripts/summarize-context.mjs RUN.json` produces the scored report and separately randomized, variant-blinded prose packet and answer key. Raters must not open the key before independent rating. The packet can still contain clues in wording; blinding is not guaranteed. AI raters are not human participants. Runtime success, network canary checks, meaningful evidence, identity limits and actual user benefit remain separate outcomes.

Source, runner, scorer and fixture hashes are recorded in `eval/context-heldout-v1.freeze.json` before the first model run. Independent development probes prompted several pre-first-run amendments while fixture contents remained withheld: remove schema-dialect metadata; use flat raw enum/quote output; stop and cancel generation after complete validated JSON; clarify prompts using four separate development inputs; and narrow model extraction to financial-request presence, payment method and verification. Existing rules supply urgency, secrecy and changed-contact claims, and gate emergency classification. Optional writing fields are generated only with a writing profile. These changes include prompt and model/rule responsibility changes, not merely transport. The final evaluated system is model-assisted extraction plus rules; all six outward gold categories and departure labels stay unchanged. Record the final source commit/hash separately from the original freeze. This is a prospective independent evaluation post-amendment, not a claim that the source remained unchanged since fixture authoring. No source or label change after inspecting held-out outcomes can retain a fresh held-out claim without a newly independent set.

These are convenience-authored synthetic cases with related pairs, not a random population sample. Counts and paired differences are descriptive. No real-world fraud accuracy, user-comprehension benefit, prevented loss, broader-language performance or 99% reliability claim follows from them. The previous failed writing-style pilot remains part of the evidence.
